# 2026-11-07 - pypdf 6.21.2 -> 6.21.4 in the caas module

Remediates seven Dependabot alerts, all created 2026-11-07T10:28:37Z to 10:28:38Z on `agent-governance-python/agent-os/modules/caas/requirements.txt` (scope: runtime). `caas` is an upstream product module, but the fix is a one-line exact-version pin bump of the same kind as the previous one (6.21.2, which its own comment records as a CVE fix), and the fork owns its security timing, so it is applied here directly instead of waiting for upstream. If upstream later bumps the same line, take the upstream value.

## Which dependencies changed and why

| Package | From | To | Files |
| --- | --- | --- | --- |
| `pypdf` | 6.21.2 | 6.21.4 | `modules/caas/requirements.txt` |
| `pypdf` (hash-pinned copy) | 6.7.5 | 6.21.4 | `modules/caas/requirements.lock` |

`requirements.txt` is the file the Docker image installs (`COPY requirements.txt` then `pip install -r`) and the file Dependabot reads. `requirements.lock` is a hand-maintained hash-pinned copy that is not produced by a lock tool (no `pip-compile` header, and the `uvicorn` entry carries no hashes) and nothing in the repo references it; it had drifted to 6.7.5, which is inside every affected range below. Only its `pypdf` block was replaced (wheel and sdist sha256 from the PyPI release metadata for 6.21.4), leaving every other entry untouched to keep churn minimal. `pyproject.toml` already declares `pypdf>=6.10.2,<7.0`, which admits 6.21.4, so it is unchanged. `examples/legal-review/requirements.txt` declares `pypdf>=6.10.2` (a floor, not a pin) and was not touched.

Every range is `pypdf < first patched`, so 6.21.4 clears all seven at once. The `caas` ingestion path (`src/caas/ingestion/processors.py`, `PdfReader(pdf_file)`) parses user-supplied PDFs, which is exactly the denial-of-service surface these advisories describe.

No new transitive package: 6.21.4 requires only `typing_extensions>=4.0` on Python below 3.11 (the module targets 3.11 and 3.12); its other requirements are optional extras.

## Breaking change risk assessment

Risk: low. `requirements.txt` moves 6.21.2 to 6.21.4 (two patch releases on the same minor), but the hand-maintained `requirements.lock` had drifted to 6.7.5 and moves 6.7.5 to 6.21.4, 14 minor releases. `processors.py` only uses `PdfReader`, `.pages` and `extract_text()`. The caas tests (Python 3.11 venv, `PYTHONPATH=src`, `-o addopts=""`) give 18 failed / 119 passed under both pypdf 6.7.5 and 6.21.4 with an identical failing-test list (in `test_context_triad` and `test_heuristic_router`, unrelated to PDFs), and a `PDFProcessor().process()` smoke on a generated PDF works under 6.21.4. The advisory fixes harden parsing limits rather than change that API surface.

## Tests run

- Scratch virtual environment (`uv venv` in the session scratch directory, `pypdf==6.21.4` plus the packages from `requirements.txt` unpinned; not committed). `import pypdf` reports 6.21.4. A generated one-page PDF written with `PdfWriter` and read back with `PdfReader` returns 1 page and runs `extract_text()` (exit 0).
- `agent-governance-python/agent-os/modules/caas/tests` with `PYTHONPATH=src` and `-o addopts=""` (the configured addopts require `pytest-cov`, which the scratch environment does not install): 119 passed, 18 failed on pypdf 6.21.4; the identical 18 tests (same names, compared by sorted `FAILED` lines) fail on pypdf 6.21.2 in the same environment, so none is caused by this change. The pdf/process-related tests selected with `-k "pdf or Pdf or PDF or process"` pass (2 passed). The cause of the 18 pre-existing failures was not investigated (the scratch environment uses unpinned dependency versions rather than the pinned set); it is out of scope here.
- Regression test: `tools/tests/test_fork_product_windows.py::test_pypdf_advisory_remediation_pins_patched_release_in_every_caas_manifest` asserts `requirements.txt` pins pypdf in `[6.21.4, 7.0.0)`, `requirements.lock` carries the same version with at least two hashes, and `pyproject.toml` still admits it.
- Monorepo gate: `pwsh -NoProfile -File tools/dev_check.ps1`.
